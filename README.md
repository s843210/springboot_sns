# 📱 Minlog (사내/커뮤니티 SNS 웹 애플리케이션)

[🇯🇵 日本語 (Japanese)](./README.ja.md)

Slack 스타일의 UI를 차용한 가벼운 SNS(소셜 네트워크 서비스) 웹 애플리케이션입니다. 
빠르고 매끄러운 화면 전환과 실시간 인터랙션(좋아요, 댓글 등)을 제공하는 데 초점을 맞춰 개발했습니다.

## 📌 프로젝트 개요
* **개발 기간**: 2026.02 ~ 2026.05
* **개발 인원**: 1인 (Full-Stack)
* **핵심 목표**: 
  * React와 Spring Boot를 완벽히 분리한 RESTful API 기반의 설계
  * JWT를 이용한 안전한 사용자 인증 시스템 구축
  * 데이터베이스 제약조건 및 React 상태 관리를 활용한 실시간 상호작용 구현

## 🛠 사용 기술
* **Backend**: Java 21, Spring Boot 3.5.10, Spring Data JPA, Spring Security
* **Frontend**: React 18, Vite, Axios, Vanilla CSS
* **Database**: MySQL (Docker를 이용한 로컬 환경 구성)
* **ETC**: JWT, dotenv (.env), Swagger (API 명세)

## 🏗 시스템 아키텍처 및 폴더 구조
* 프론트엔드(React, 3000번 포트)와 백엔드(Spring Boot, 8080번 포트)를 완전히 분리하여 개발했습니다.
* 로컬 환경에서 CORS 문제를 피하기 위해 Vite의 Proxy 설정을 활용해 통신합니다.
* 사용자가 로그인하면 백엔드에서 발급한 JWT를 프론트엔드의 `localStorage`에 저장하고, 이후 모든 요청은 Axios Interceptor를 통해 Authorization 헤더에 토큰을 자동으로 담아 보냅니다.

## ✨ 핵심 기능 구현 디테일

### 1. 보안 및 인증 (JWT)
Spring Security의 `Filter` 로직을 커스텀하여, 요청이 들어올 때마다 토큰의 유효성을 검사하는 `JwtRequestFilter`를 구현했습니다. 만료되거나 변조된 토큰일 경우 프론트엔드의 Axios Interceptor에서 401 에러를 캐치해 자동으로 로그아웃 시키도록 처리했습니다.

### 2. 반응형 소셜 기능 (좋아요 / 댓글)
* **좋아요**: 한 사용자가 같은 게시글에 여러 번 좋아요를 누르는 것을 방지하기 위해, MySQL 테이블에 `article_id`와 `user_id`를 묶어 유니크(Unique) 제약조건을 걸었습니다. 프론트엔드에서는 서버 응답을 기다리지 않고 미리 하트 버튼 색상을 바꾸는 낙관적 업데이트(Optimistic UI) 방식을 차용해 반응성을 높였습니다.
* **댓글**: 포스트카드 컴포넌트가 렌더링될 때 서버에서 최신 댓글 목록을 가져오고, 사용자가 댓글을 작성하면 화면의 리스트 배열(State)에 즉시 추가하여 새로고침 없이도 내가 쓴 댓글을 바로 볼 수 있게 만들었습니다.

### 3. 이미지 업로드 시스템
외부 스토리지(S3 등)를 사용하기 전, 기초적인 로컬 파일 서빙 방식을 학습하기 위해 내장된 파일 업로드 로직을 직접 구현했습니다. 파일명 중복을 막기 위해 `UUID`를 생성하여 확장자를 붙여 저장하고, `WebMvcConfigurer`를 통해 `/uploads/**` 경로로 들어오는 요청을 로컬 디렉토리와 매핑해 이미지를 띄워줍니다.

## 🚀 트러블슈팅 (문제 해결 과정)

**1. 파일 업로드 시 500 에러 (상대 경로 이슈)**
초기에는 `MultipartFile`을 저장할 때 `uploads/`라는 상대 경로를 사용했습니다. 그런데 테스트 코드를 돌리거나 로컬 환경에서는 잘 되다가도 톰캣 서버에서 500 에러가 나는 간헐적 문제가 있었습니다. 
원인을 찾아보니, 톰캣 환경에서는 상대 경로를 입력하면 프로젝트 폴더가 아니라 운영체제의 임시 폴더(`java.io.tmpdir`)를 기준으로 잡는다는 것을 알게 되었습니다. 이를 해결하기 위해 `Paths.get(UPLOAD_DIR).toAbsolutePath().normalize()` 코드를 통해 어떤 환경에서든 프로젝트 루트 디렉토리의 절대 경로를 찾아 저장하도록 강제하여 문제를 해결했습니다.

**2. 댓글 작성 후 즉시 화면에 반영되지 않던 문제**
처음 댓글 기능을 붙였을 때, 댓글을 작성하고 전송을 눌러도 화면에는 카운트가 올라가지 않고 기존 댓글만 보였습니다. "새로고침"을 해야만 서버에서 데이터를 다시 가져왔기 때문입니다.
이러한 답답한 UX를 고치기 위해, React의 `useEffect` 훅을 이용해 포스트가 렌더링될 때 댓글을 비동기로 Fetch 해오고, 전송 버튼을 누르는 순간 서버에 POST 요청을 보냄과 동시에 성공하면 최신 목록을 다시 불러오도록 로직을 수정했습니다. 결과적으로 작성자 본인이 쓴 댓글을 즉시 확인할 수 있게 되었습니다.

**3. JWT 시크릿 키 깃허브 노출 이슈 및 환경 변수 분리**
개발 편의를 위해 `application.properties`에 JWT 시크릿 키와 DB 비밀번호를 하드코딩해서 사용했습니다. 하지만 포트폴리오를 위해 깃허브에 코드를 올리려다 보니 심각한 보안 취약점이 될 수 있음을 깨달았습니다.
곧바로 `spring-dotenv` 라이브러리를 설치하고, 프로젝트 최상단에 `.env` 파일을 만들어 민감한 키들을 모두 옮겼습니다. 기존에 사용하던 키는 탈취되었을 수도 있다고 가정하여 폐기하고 완전히 새로운 키를 발급받았습니다. 마지막으로 `.gitignore`에 `.env`를 추가해 소스코드 저장소에는 빈 껍데기인 `.env.example`만 올라가도록 조치했습니다.

## 🏁 실행 방법

### Backend (Spring Boot)
```bash
# 1. 최상위 디렉토리에 .env 파일 생성 및 값 채우기 (DB 및 JWT 정보)
# 2. 서버 실행
./gradlew bootRun
```

### Frontend (React + Vite)
```bash
cd sns-frontend
npm install
npm run dev
# 기본 접속: http://localhost:3000
```
