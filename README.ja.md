# 📱 Minlog (社内/コミュニティSNSウェブアプリケーション)

[🇰🇷 한국어 (Korean)](./README.md)

SlackスタイルのUIを採用した、軽量なSNS（ソーシャル・ネットワーク・サービス）ウェブアプリケーションです。 
スムーズな画面遷移とリアルタイムのインタラクション（いいね、コメントなど）の提供に重点を置いて開発しました。

## 📌 プロジェクト概要
* **開発期間**: 2026.02 ~ 2026.05
* **開発人数**: 1人 (Full-Stack)
* **核心目標**: 
  * ReactとSpring Bootを完全に分離したRESTful APIベースの設計
  * JWTを利用した安全なユーザー認証システムの構築
  * データベース制約およびReactの状態管理を活用したリアルタイム相互作用の実装

## 🛠 技術スタック
* **Backend**: Java 21, Spring Boot 3.5.10, Spring Data JPA, Spring Security
* **Frontend**: React 18, Vite, Axios, Vanilla CSS
* **Database**: MySQL (Dockerを利用したローカル環境の構築)
* **ETC**: JWT, dotenv (.env), Swagger (API仕様書)

## 🏗 システムアーキテクチャおよびフォルダ構造
* フロントエンド(React、ポート3000)とバックエンド(Spring Boot、ポート8080)を完全に分離して開発しました。
* ローカル環境でのCORS問題を回避するため、Viteのプロキシ(Proxy)設定を活用して通信します。
* ユーザーがログインすると、バックエンドで発行されたJWTをフロントエンドの`localStorage`に保存し、その後のすべてのリクエストはAxios Interceptorを通じてAuthorizationヘッダーにトークンを自動的に付与して送信します。

## ✨ 主要機能の実装ディテール

### 1. セキュリティと認証 (JWT)
Spring Securityの`Filter`ロジックをカスタムし、リクエストが送信されるたびにトークンの有効性を検証する`JwtRequestFilter`を実装しました。期限切れや改ざんされたトークンの場合、フロントエンドのAxios Interceptorで401エラーをキャッチし、自動的にログアウト処理を行うように設計しました。

### 2. インタラクティブなソーシャル機能 (いいね / コメント)
* **いいね**: 1人のユーザーが同じ投稿に何度もいいねを押すのを防ぐため、MySQLテーブルに`article_id`と`user_id`を組み合わせたユニーク(Unique)制約を設定しました。フロントエンドでは、サーバーの応答を待たずにハートボタンの色を先に変更する「楽観的UI更新(Optimistic UI)」方式を採用し、応答性を高めました。
* **コメント**: ポストカードコンポーネントがレンダリングされる際にサーバーから最新のコメントリストを取得し、ユーザーがコメントを書き込むと、画面上のリスト配列(State)に即時追加することで、ページを更新することなく自分が書いたコメントをすぐに確認できるようにしました。

### 3. 画像アップロードシステム
外部ストレージ(S3など)を使用する前に、基本的なローカルファイルサービング方式を学習するため、内蔵のファイルアップロードロジックを直接実装しました。ファイル名の重複を防ぐために`UUID`を生成して拡張子を付加して保存し、`WebMvcConfigurer`を通じて`/uploads/**`パスへのリクエストをローカルディレクトリとマッピングして画像を表示します。

## 🚀 トラブルシューティング (問題解決のプロセス)

**1. ファイルアップロード時の500エラー (相対パスの問題)**
初期は`MultipartFile`を保存する際、`uploads/`という相対パスを使用していました。しかし、テストコードの実行やローカル環境では正常に動作するものの、Tomcatサーバー上で500エラーが発生する断続的な問題がありました。
原因を調査したところ、Tomcat環境では相対パスを入力するとプロジェクトフォルダではなく、オペレーティングシステムのテンポラリフォルダ(`java.io.tmpdir`)が基準になることが判明しました。これを解決するため、`Paths.get(UPLOAD_DIR).toAbsolutePath().normalize()`コードを用いて、どのような環境でもプロジェクトのルートディレクトリの絶対パスを取得して保存するように強制し、問題を解決しました。

**2. コメント投稿後に画面に即座に反映されない問題**
最初にコメント機能を実装した際、コメントを入力して送信ボタンを押しても画面のコメント数が増えず、既存의コメントしか表示されませんでした。「手動で更新(リロード)」しなければ、サーバーからデータを再取得しなかったためです。
この不便なUXを改善するため、Reactの`useEffect`フックを利用してポストがレンダリングされる際にコメントを非同期でFetchし、送信ボタンを押した瞬間にサーバーにPOSTリクエストを送ると同時に、成功した場合は最新のリストを再取得するようロジックを修正しました。結果として、投稿者本人が書き込んだコメントを即座に確認できるようになりました。

**3. JWTシークレットキーのGitHub露出問題および環境変数の分離**
開発の利便性のために、`application.properties`にJWTシークレットキーとDBパスワードをハードコーディングしていました。しかし、ポートフォリオ公開のためにGitHubにコードをアップロードしようとした際、これが深刻なセキュリティ上の脆弱性になることに気づきました。
すぐに`spring-dotenv`ライブラリを導入し、プロジェクトの最上位ディレクトリに`.env`ファイルを作成して機密性の高いキーをすべて移行しました。既存のキーは流出した可能性があると仮定して廃棄し、完全に新しいキーを発行しました。最後に、`.gitignore`に`.env`を追加し、ソースコードリポジトリにはテンプレートである`.env.example`のみがアップロードされるように対策を講じました。

## 🏁 起動方法

### Backend (Spring Boot)
```bash
# 1. 最上位ディレクトリに.envファイルを作成し、値を設定 (DBおよびJWT情報)
# 2. サーバーの実行
./gradlew bootRun
```

### Frontend (React + Vite)
```bash
cd sns-frontend
npm install
npm run dev
# デフォルト接続先: http://localhost:3000
```
